# Phase 8 · Order Assistant

**Goal.** A read-only chat app where any user asks about cases in plain language and gets an answer with data cards and deep links, instead of phoning another team. It replaces Joule on trial.

**Duration.** 4–5 days.

**Depends on.** Phase 2 (A1 read access, `canRead`), Phases 3, 5, 6 (tool results), Phase 4 (`runToolLoop`).

**Blueprint.** §5.3, §6.2, §8.3 scenario 6.

**Not a sixth agent.** It produces no recommendations, is not part of the case flow, and has **no path to any action**.

---

## 1. Back end: `OrderAssistantService`

```cds
service OrderAssistantService @(requires: ['Sales','SupplyPlanner','ProductionPlanner']) {
  action ask(conversationId: UUID, caseId: String, message: String)
    returns { conversationId: UUID; answerText: String; verified: Boolean;
              cards: LargeString; links: LargeString; };
  @readonly entity MyConversations as projection on ChatConversation where owner = $user;
  @readonly entity MyMessages      as projection on ChatMessage      where conversation.owner = $user;
  action newConversation(caseId: String) returns UUID;
}
```

### Read-only tools (all strict JSON schemas, all run as the calling user)

| Tool | Implementation |
|---|---|
| `listCases(filter)` | A1 query with `canRead`; filters lane, status, waitingForRole, penaltyRisk, date range |
| `getCase(caseId)` | Header, status, waiting for, latest recommendations and decisions |
| `getCaseTimeline(caseId)` | `CaseTimeline` view (Phase 2) |
| `getSupplyPicture(caseId)` | Stored A3 `SupplyResult` snapshot |
| `getCapacityOptions(crId)` | Stored A4 options, load before/after, scores, override flags |
| `getSalesOrder(so)` | Adapter read (Phase 3) |

- Each tool checks `canRead(user, case)` first; unauthorized → tool error "not found" (no information leak).
- Tool registry is a fixed list; there is **no** write tool, and a unit test asserts every registered handler is read-only (no `UPDATE`/`INSERT`/action calls except chat storage).

### `ask` flow
1. Load or create the conversation (owner check).
2. Build messages: fixed system prompt (scope, read-only, "use only tool results", answer action requests with the deep link), prior turns, then the user message as delimited data. Add `caseId` context if present.
3. `llm.runToolLoop()` with max 6 tool calls (from `PlanningParameters.maxToolCallsPerQuestion`), masking applied to tool results.
4. **Cards and links are built in CAP from the tool results of this turn**, not from LLM text:
   - case header card (ID, lane, status, waiting for, requested/confirmed date),
   - table card (material tree or capacity options),
   - deep links ("Open FC-0001 in Supply Planning Workbench"), chosen by the user's role and the case status.
5. Guards:
   - Number check: every number, date and ID in `answerText` must appear in this turn's tool results; otherwise answer = *"I couldn't verify this answer. See the data below."* and `verified = false`.
   - Out of scope → *"I can only answer questions about order feasibility cases."*
   - LLM unavailable → no text; cards for the case ID found in the question.
6. Store `ChatMessage` (question, answer, tool calls, model ID, tokens). Demo retention: cleared on app restart.

### Action requests
"Confirm FC-0001 to the customer" → the answer explains the assistant can't act, states the current status from `getCase` (e.g. not yet `SUPPLY_CONFIRMED`), and links to the case app. **No status change and no audit row** (scenario 6 test).

## 2. Front end: SAPUI5 freestyle app (`app/order-assistant`)

| Element | Detail |
|---|---|
| Message list | User questions and assistant answers; each answer labelled **"Generated by AI, check the data cards"**. |
| Cards | Case header card, table card, deep link buttons, rendered from `cards`/`links` JSON. |
| Suggested questions | Chips when the conversation is empty, e.g. *What's blocking FC-0001?*, *Show my HIGH cases waiting for me*, *Which cases have penalty risk this week?* |
| Case context | When opened with `?caseId=FC-0001` (from "Ask about this case"), show the case as context at the top. |
| New conversation | Button that calls `newConversation`. |
| Busy state | Indicator while `ask` runs; input disabled. |
| Name | Always **"Order Assistant"**. Never "copilot". |

Navigation: inbound `OrderAssistant-display` with optional `caseId`; outbound deep links via cross-app navigation to the three case apps.

## 3. Tests (scenario 6 + guardrails)

- [ ] *"What's blocking FC-0001?"* (Sales, case `WITH_PRODUCTION`) → mentions waiting for Production Planning on CR-0001, two options, O-ALT recommended; case card; link to Sales Order Feasibility.
- [ ] *"Compare the options for CR-0001"* (Production Planner) → table card with O-ALT and O-MOVE scores, O-MOVE "needs override", link to Production Capacity Workbench.
- [ ] *"Confirm FC-0001 to the customer"* → explanation + link; case status and audit log unchanged.
- [ ] A user without access to a case gets no data about it.
- [ ] Invented number in answer → verification fallback text, cards still shown.
- [ ] Tool loop stops at 6 calls.
- [ ] Off-topic question → scope reply.
- [ ] Conversation of user A not readable by user B.
- [ ] All of the above pass with the mock LLM provider (scripted tool plans); run once live in `[demo-live]`.

## Checklist (rules)

- [ ] Same masking and number check as the agents.
- [ ] No recommendations generated or stored by the assistant.
- [ ] No "copilot" in the app, service code or texts.

## Exit criteria

- [ ] "Ask about this case" from each case app opens the assistant with the case in context.
