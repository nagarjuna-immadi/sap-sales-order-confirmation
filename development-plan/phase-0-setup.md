# Phase 0: Setup and API verification

[← Development plan](README.md) · Next: [Phase 1](phase-1-core-model.md)

**Goal:** a CAP project that starts with mocked S/4 services and returns the §8 demo orders.

## 0.1 Verify the Hub APIs (manual)

For each API in §4.2: `API_SALES_ORDER_SRV`, `API_PRODUCT_AVAILY_INFO_BASIC`, `API_MATERIAL_STOCK_SRV`, `API_BILL_OF_MATERIAL_SRV`, `API_PRODUCT_SRV`, `API_PLANNED_ORDERS`, `API_PRODUCTION_ORDER_2_SRV`, `API_WORK_CENTERS` (all from the S/4HANA **private cloud / on-premise** package):

- [ ] Confirm the state is ACTIVE on api.sap.com and note the OData version (V2 or V4).
- [ ] Download the EDMX to `srv/external/<API>.edmx`.
- [ ] Note the exact service path and the sandbox base URL from the **Try Out** page.
- [ ] Run **Try Out** and record whether it returns rows.
- [ ] Record the result (Yes / Empty / No) in a "Hub sandbox" column added to the blueprint §4.2 table.
- [ ] Confirm that capacity load per day has **no** API in the sandbox (§4.2), so it stays a local mock entity.
- [ ] Note the sales order business event specification (*SalesOrder Created / Changed*) payload, for the "Simulate S/4 event" button in phase 2.

## 0.2 Scaffold the project

- [ ] Add `.gitignore` first: `.env`, `default-env.json`, `.cdsrc-private.json`, `node_modules/`, `gen/`, `mta_archives/`, `*.mtar`, `*.sqlite`.
- [ ] Run `cds init` in place, as an ES module (`"type": "module"`), then add `@sap/cds`, `@cap-js/sqlite`, `@sap/xssec`, and (dev) `@sap/cds-dk`.
- [ ] `package.json` scripts: `start`, `watch` (`cds watch`), `watch-hybrid` (`cds watch --profile hybrid`).
- [ ] Add an ESLint rule (`no-restricted-imports`) so `@anthropic-ai/sdk` can only be imported in `srv/lib/llm/` (phase 7).
- [ ] Add a CI grep check that fails on the word "copilot" in `app/`, `srv/` and `db/`.
- [ ] Put the run commands into `CLAUDE.md`.

## 0.3 Import the S/4 services

- [ ] Run `cds import srv/external/<API>.edmx --as cds` for each API from 0.1.
- [ ] In `package.json` → `cds.requires`, add each API (`kind: odata-v2` or `odata`, `model: srv/external/<API>`). No credentials yet; the `[hybrid]` and `[production]` entries come in phase 6.
- [ ] Set `max_get_url_length: 8192` on each service (lesson from the TM project: CAP's default turns long GETs into `POST $batch`, which the sandbox rejects with `403 x-csrf-token: Required`).
- [ ] Fix any import errors the compiler reports (as with `not null default null` in the TM project). Note the fix here, so it can be redone after every re-import.
- [ ] Write down the real entity set, key and field names in the table [below](#real-s4-names). Most important: the **delivery priority** property on the sales order item (§7 A2).

## 0.4 Mock data (`srv/external/data/`)

Generated by `node scripts/gen-mock-data.js [--base YYYY-MM-DD]`. Dates are relative to the base date (default: today), so re-run it when the dates get stale. All values come from §8 and must stay consistent across files.

- [ ] Sales orders and items: `SO-5001` and `SO-5004` (NORMAL, 100 × FG-100, due D+9), `SO-5005` (C-1001, 100 × FG-100, priority `01`, requested D+5), `SO-5006` (C-1002, 50 × FG-300, priority `02`, requested D+6), `SO-5007` (C-1003, 10 × FG-300, priority `03`).
- [ ] Products: FG-100 Gearbox Assembly, SFG-200 Gear Housing, RAW-1 Aluminium Casting, RAW-2 Bearing Set, FG-300 Pump Unit, with MRP lot-size data (FG-100 exact lot size).
- [ ] BOM: FG-100 → 1 SFG-200; SFG-200 → 1.05 RAW-1 + 0.05 RAW-2.
- [ ] Stock plant 1000: FG-100 0, SFG-200 0, RAW-1 150, RAW-2 20, FG-300 20. Plant 1100: FG-300 200.
- [ ] Work centers plant 1000: WC-MACH-01 200/day, WC-ASSY-01 100/day (primary for FG-100), WC-ASSY-02 80/day (alternative production version).
- [ ] Planned / production orders: SO-5001 on WC-ASSY-01 D+1, SO-5004 on WC-ASSY-01 D+2. No open receipts for FG-100.
- [ ] Data that has no S/4 API in the sandbox goes into local mock entities in phase 1 (capacity load per day, last movement and monthly demand for slow movers, customers with penalty clause).
- [ ] CSV file names must match the imported namespace and entity (`<namespace>-<Entity>.csv`). CAP reads an empty cell as `NULL`, so a `not null` string that should be empty is written as a quoted `""`.
- [ ] **ATP:** `API_PRODUCT_AVAILY_INFO_BASIC` is a function, which CAP's generic mock does not compute. Note here how phase 2 handles it (a mock handler that calculates from the stock CSV).
